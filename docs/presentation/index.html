Problem 1

Right config, wrong image.

What happened

00:00 of 500s
  1. 1A release adds a new config value. Terraform applies it first.
  2. 2Cloud Run makes a revision: new config + old image.
  3. 3Old code can’t read the value. Every tenant gets errors until the new image lands.
  4. 4A person noticed first, not an alert.
  5. 5The image is rebuilt per environment, so prod isn’t what was tested.

What we changed

0 user errors
  • One release, one unit. Image digest, config and revision shape ship together as one Cloud Run revision.
  • Terraform stays out of the way. It owns the service shell and ignores the revision.
  • Config checked three times. In CI, when the release is rendered, and when the container starts.
  • Build once, promote by digest. The bytes tested in dev are the bytes in prod.
  • Machines notice first. Canary, a 5xx alert and deploy markers on the dashboard.

Problem 2

The review queue.

Agents open more PRs, human review is the slowest step, and compliance still wants a second person on production changes. So humans should review less, and only where it matters.

risk:low

No human

Docs and patch or minor dev-tooling updates merge themselves once CI is green.

risk:medium

One human

App code, including agent-written fixes. Any one reviewer who isn’t the author. Bot approvals never count.

risk:high

Code owner

Infra, deploy specs, workflows, migrations, config schema and major upgrades.

The compliance second person approves the release: one approval on the exact build going to production, recorded by GitHub, instead of a human on every bot PR.
