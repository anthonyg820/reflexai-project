The app

RehearseAI: practice the hard conversations.

A training simulator for front-line staff. Talk to a simulated caller or customer, get coached as you go, and get scored against a rubric.

What it does

  1. 1
    Pick a scenarioA persona with a situation: “first-time caller, high anxiety”, “customer disputing a fee”. Each has a difficulty, a channel and a target rubric.
  2. 2
    Practice the conversationType replies; the simulated person answers. A live coach panel nudges you as you go (“try reflecting their words back”).
  3. 3
    Get scored and coachedEnd the session for a rubric score with pass / fail, four coaching criteria and the key moments that moved the score.

Problem 1

Right config, wrong image.

What happened

00:00 of 500s
  1. 1A release adds a new config value. Terraform applies it first.
  2. 2Cloud Run makes a revision: new config + old image.
  3. 3Old code can’t read the value. Every tenant gets errors until the new image lands.
  4. 4A person noticed first, not an alert.
  5. 5The image is rebuilt per environment, so prod isn’t what was tested.

What we changed

0 user errors
  • One release, one unit. Image digest, config and revision shape ship together as one Cloud Run revision.
  • Terraform stays out of the way. It owns the service shell and ignores the revision.
  • Config checked three times. In CI, when the release is rendered, and when the container starts.
  • Build once, promote by digest. The bytes tested in dev are the bytes in prod.
  • Machines notice first. Canary, a 5xx alert and deploy markers on the dashboard.

CI rejectsrenderer rejectsstartup probe rejectsalert fires

Problem 2

The review queue.

Agents open more PRs, human review is the slowest step, and compliance still wants a second person on production changes. So humans should review less, and only where it matters.

Incoming

Queue sorted. Humans only see 4 of 6.

risk:low

No human

Docs and patch or minor dev-tooling updates merge themselves once CI is green.

risk:medium

One human

App code, including agent-written fixes. Any one reviewer who isn’t the author. Bot approvals never count.

risk:high

Code owner

Infra, deploy specs, workflows, migrations, config schema and major upgrades.

The compliance second person approves the release: one approval on the exact build going to production, recorded by GitHub, instead of a human on every bot PR.

Connection

DATABASE_URL lives in Secret Manager (rehearse-<env>-database-url); the release references it by name

Direct URL, TLS on: pooling off, because the migration lock needs one session

Pool: 5 connections per instance, 15 s to connect while a sleeping branch wakes

Lesson learned

Neon suspends idle computes after 5 minutes and drops every connection (57P01).

That crashed the API until the pool handled it: ResilientPool logs it, replaces the connection, and retries a single statement once.

A test now cuts every connection mid-run and checks the API keeps answering.

Why Neon: it’s plain Postgres (where ReflexAI is heading), it costs nothing at this size, and branching makes a database per PR preview cheap later.
